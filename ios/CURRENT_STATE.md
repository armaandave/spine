## Live API

- The app always uses live API repositories via `AppRepositories.current()`.
- Authenticated API requests retry once through `POST /api/v1/auth/refresh/` on a 401 when a refresh token exists; tokens are cleared only if refresh is unavailable or fails.
- Library uses paged `GET /api/v1/tracking/?media_type=<type>` results for Tracked, `GET /api/v1/tracking/?media_type=<type>&status=Planning` for Planning, and follows the API `next` page cursor with `page=<cursor>`; no app-shipped cache or fake library data is used.
- Media detail uses `GET /api/v1/media/{source}/{media_type}/{media_id}/` plus `GET /api/v1/tracking/{source}/{media_type}/{media_id}/` for the authoritative saved tracking/progress state when an item is tracked.
- TV season detail uses `GET /api/v1/media/{source}/tv/{media_id}/seasons/{season_number}/` from season cards on a TV show detail page.
- Poster customization uses `GET /api/v1/media/{source}/{media_type}/{media_id}/posters/` and `PUT /api/v1/media/{source}/{media_type}/{media_id}/poster/`.
- Live media detail now consumes normalized `cast`, `crew`, `seasons`, `episodes`, `related_sections`, `external_ratings` (including Steam percentage/review counts and optional provider-page `url` values), `details`, custom posters, backdrop images, and `community.rating_distribution` from the API. Season pages render top-level episode number, title, full date/runtime/rating, overview, and episode image when available.
- People pages use `GET /api/v1/people/tmdb/{person_id}/` through the live `PeopleRepository`. The endpoint is expected to return person profile fields plus mixed movie/TV credits as standard `MediaSummary` objects sorted by TMDB popularity.
- Live review fetch still uses `GET /api/v1/media/{source}/{media_type}/{media_id}/reviews/`; season pages use the TV media path with `season_number` query params and render available review cards.
- Media log uses `POST /api/v1/diary/`, query-driven `GET /api/v1/diary/tags/?q=<text>`, `PATCH /api/v1/tracking/{source}/{media_type}/{media_id}/`, `POST /api/v1/tracking/{source}/{media_type}/{media_id}/actions/consume/`, `POST /api/v1/tracking/{source}/tv/{media_id}/seasons/{season_number}/watch/`, `POST /api/v1/tracking/{source}/book/{media_id}/progress/`, and `POST /api/v1/tracking/{source}/book/{media_id}/complete/`.
- Profile Tags uses `GET /api/v1/diary/tags/?mine=true&all=true` for the full personal tag list. The response is still the existing `{ "results": [...] }` tag-suggestion shape.
- Media detail progress updates use `POST /api/v1/tracking/{source}/book/{media_id}/progress/` for books and `PATCH /api/v1/tracking/{source}/{media_type}/{media_id}/` for game percent progress.
- Diary uses `GET /api/v1/diary/` for the list and `GET /api/v1/diary/{id}/` for row detail; entry creation remains routed through media detail logging.
- Tags use `GET /api/v1/diary/?tag=<tag>` and the existing paged diary response shape. The iOS repository follows diary pages so tag diary/grid views are complete for the API response.
- Profile uses `GET/PATCH /api/v1/me/` for identity, counts, profile fields, preferences, and Hall of Fame slots, `POST/DELETE /api/v1/me/avatar/` for profile photos, `PATCH /api/v1/me/preferences/` for mobile preferences, `POST /api/v1/me/password/` for password changes, `PUT/DELETE /api/v1/me/hof/{media_type}/` for favorite edits, plus `GET /api/v1/diary/` for recent activity.
- Stats uses authenticated `GET /api/v1/stats/me/summary/` with `start_date=all&end_date=all` or inclusive calendar-year dates. The same documented contract is available at `GET /api/v1/users/{username}/stats/summary/`. The UI consumes `completed_count` for all-time totals and per-type mix, `unique_logged_count` for year headlines, and diary-scoped activity/ratings/reviews/repeats/ranked media/release years/genres/languages. `tracked_count` and raw statuses remain decoded for compatibility but never substitute for completion. Mixed native five-star and ten-point rating buckets are normalized onto the chart's ten-point axis, while ranked badges retain their native `/5` or `/10` label. No app-shipped stats fixtures or provider calls are used.
- Stats Most Logged uses `most_logged_total` from the summary (falling back to the preview count on older servers, which hides "See all") and paged `GET /api/v1/stats/me/most-logged/` (or `/users/{username}/stats/most-logged/`) with the same date range plus optional `media_type`, `page`, and `page_size=48`.
- Profile Lists uses `GET /api/v1/lists/` for overview rows and optional capped `preview_items` poster strips, `GET /api/v1/lists/{id}/` plus paged `GET /api/v1/lists/{id}/items/` for complete edit drafts, `GET /api/v1/meta/` and `GET /api/v1/media/search/` for the live composer picker, `POST/PATCH /api/v1/lists/` for list metadata, `POST/DELETE /api/v1/lists/{id}/items/` for staged membership changes, and `PATCH /api/v1/lists/{id}/items/reorder/` for the complete final order. No backend or shared API contract changes were required.
- Home uses `GET /api/v1/me/`, `GET /api/v1/tracking/?media_type=<type>&status=In%20progress`, and `GET /api/v1/users/{username}/activity/?page_size=6`. The full Activity screen uses the same documented activity endpoint with `page_size=25` and follows its `next_cursor` URL by sending the opaque `cursor` query value. No backend or shared API contract change was required.
- No production-facing fake rating distributions, Goodreads labels, reading progress, author counts, or recommendation placeholders are rendered.
- Movie detail rating chips hide TMDB for now and use bundled IMDb, Letterboxd, and Rotten Tomatoes logo assets when those sources are present.

## Known Gaps

- Poster customization is currently limited to TMDB movies and top-level TV shows; seasons/books/games are not wired in iOS yet.
- Log editing is new-entry only; editing or deleting existing diary entries remains unwired.
- Diary entry detail is wired from Diary rows; public permalink routing and social-like actions are not included yet.
- Tag pages require backend support for exact `tag` filtering on `GET /api/v1/diary/`; the app does not client-filter incomplete diary pages.
- Profile Tags depends on the deployed backend including `all=true` support on `GET /api/v1/diary/tags/`; older backend builds still return the autocomplete-capped 10 results.
- Episode-level logging is not included in the iOS log page yet.
- External ratings, credits, related sections, episodes, seasons, and custom poster URL are typed on iOS; live usefulness depends on provider metadata availability.
- People pages depend on the backend people endpoint being deployed. Non-TMDB credits, books/authors, comics, and provider credits without person ids remain display-only.
- The bottom nav replica on media detail is page-local UI that routes global tab selection through the provided tab callback.
- Home Activity remains the authenticated user's own activity. Switching the actor-aware rows to the documented followed-user `/api/v1/feed/` endpoint and adding social interactions are deferred.
- Stats requires the expanded stats-summary backend in this checkout to be deployed. The endpoint exposes paused/dropped counts but no aggregate factual progress, and the available live rows do not provide usable maxima, so paused and dropped progress is deliberately excluded until the backend supplies normalized completed-unit totals. Likes are an all-time snapshot and are shown only in All Time. Genre/language sections may be partial when local metadata coverage is incomplete. Rating buckets still omit explicit scale metadata, so iOS infers the app's native movie/music/book five-star scale; a future contract field should replace that inference.

## How To Run

- Open `ios/Spine/Spine.xcodeproj`.
- Scheme: `Spine`.
- Default Simulator: iPhone 17 (iPhone 16 is not installed on this Mac).
- Default API configuration: `ios/Spine/Spine/Core/Environment/AppConfig.swift`.
- Optional live API override: set `SPINE_API_BASE_URL`.
- XcodeBuildMCP defaults: `.xcodebuildmcp/config.yaml` (project, scheme, simulator, bundle ID).
- Agents with XcodeBuildMCP: use `simulator/build-and-run` after meaningful UI changes; `session_show_defaults` to verify config loaded.
- Build command (fallback):

```bash
DEVELOPER_DIR=/Applications/Xcode-26.5.0.app/Contents/Developer \
  xcodebuild -project ios/Spine/Spine.xcodeproj -scheme Spine \
  -destination 'platform=iOS Simulator,name=iPhone 17' build
```
